# 第一版可靠 MVP：收敛开发计划

更新：2026-10-08。依据：用户要求收敛实现、加速开发、基本功能齐全，以及 [PRD](./PRODUCT_REQUIREMENTS.md)。本文件是当前开发执行主线；[旧指南](./DEVELOPMENT_GUIDE.md)保留 API 合同、历史实验和详细验收资料。

2026-10-06 最新确认：继续 Desktop 开发。存储改为 Notebook 自有“一个元数据 JSON＋多个不可变笔记 data JSON”，复用现有 Snapshot、笔记、标签、查询和串行提交逻辑，不再等待 Storage Domain 补接口。先支持单 Desktop 实例；多进程同时写同一库、应用内坏库恢复暂缓。保存损坏停写、临时文件替换、失败保草稿和未知提交停写。首版需几千条或较长笔记，正式库有效文件总预算采用 50 MiB，元数据与 data 一起计入；不采用旧1 MiB临时预览限额。划线允许会话＋原文＋上下文文本锚点，不要求官方 messageId；单条可识别正文内选区，多处匹配不自动定位、不伪造官方消息身份。会话活动时间缺失时的排序口径仍另行确认。

2026-10-06 界面调整（0.0.18）：按用户要求删除卡片“转换类型”操作，摘录工具条默认只显示操作按钮，标签支持快捷保存、选择及新建。统一左侧菜单打开原生右边栏，删除输入区重复入口。隐藏未形成完整恢复流程的 JSON 预览入口，保留 JSON 导出；整库恢复仍暂缓。此说明优先于下文历史候选和类型转换界面要求。详见[0.0.18 记录](./evidence/notebook-ui-0.0.18.md)。

## 1. 交付目标与范围

第一版在 Desktop 本机完成“选择原文 → 划线或记笔记 → 保存 → 查询和编辑 → 定位来源 → 导出备份”的使用流程。应用内受控整库恢复留待后续。独立 Web 继续暂缓。优先复用已写模块，按本轮使用流程交付，停止增加与当前交付无关的基础设施。

范围以 PRD 和下列用户确认的本轮调整为准。应用内坏库替换和完整 JSON 恢复按最新决定暂缓；手工保存切片和功能预览不能冒充正式 MVP。多 Host 同库写入、共享目录、云同步、通用增量导入、Agent/MCP 工具不进入本轮。

2026-10-05 评审后范围调整：

- 性能先暂缓：本轮不安排性能专项优化、规模基准和 NFR-001/AC-013 数值验收，不作为本轮准出条件，也不标记为通过。输入限额、超限明确拒绝、数据完整性及宿主资源释放要求保留。
- 快捷标签设置和最近使用行为移出本轮开发范围：不开发快捷标签隐藏、固定、顺序调整、最近使用菜单及最近使用时间展示。保留默认快捷标签划线、普通标签创建/选择/重命名/合并/删除、使用数量和影响确认；预置标签仍按稳定 Tag ID 识别，删除后不自动重建。
- 列表和搜索先按当前开发计划实现，本轮不补来源状态筛选（来源已归档、来源不可用）、扩展搜索字段及搜索结果匹配词高亮。已有查询能力继续复用，不因暂缓而删除。来源打开、归档处理和来源不可用时保留快照仍按 C 实现。

上述暂缓项不计入本轮完成条件；交付时注明范围，不能声称原 PRD 全项已验收。其他未调整的产品规则继续沿用 PRD。

| 第一版功能 | 必须交付的行为 |
|---|---|
| 手工笔记 | 新建、标题与 Markdown 正文编辑、安全预览、保存、详情、返回列表 |
| 会话摘录 | 已提交 user/assistant 消息内局部选择；无标签划线、快捷标签、补充笔记、原文改写 |
| 引用与高亮 | 准确引用只读；有可靠映射则保存原始 Markdown，否则明确纯文本；保存后及重新渲染后恢复高亮 |
| 笔记库 | 全部、当前会话、当前工作区；关键词、类型、标签 AND/OR、无标签及时间筛选；稳定排序与批量选择 |
| 标签 | TODO、重要、待验证初始化一次；创建、选择、重命名、合并、删除及影响确认 |
| 编辑与删除 | 编辑保留身份与来源；移除正文确认；普通删除入回收站、恢复、永久删除确认 |
| 来源与输入框 | 打开来源会话，归档操作确认；可定位时定位；来源不可用时保留快照；复制 Markdown、确认追加或替换最新草稿，不自动发送 |
| 文件 | 按列表顺序导出一个 UTF-8 Markdown，包含 PRD 元数据和选项；导出完整 JSON 备份。受控整库恢复留待后续 |
| 持久化 | 保存成功才清草稿；失败可重试；刷新和重启读回；损坏/未知版本停写，不空库覆盖 |

除上述暂缓项外，列表和归档来源等完整规则沿用 PRD 对应 FR，不以此表的简述替代它们。现有 1 MiB 整库和 256 KiB 请求只是预览默认值，不能称为已经批准的产品上限。容量与性能专项评估暂缓；本轮如沿用技术限额，须说明实际限制，不宣称已验证 PRD 的数据规模。

## 2. 当前起点与最小实现

本轮起始核对工作区为 0.0.13，检查结束时 package.json 已为 0.0.14；本次仅编辑文档，不包含该版本变更。正式 Host 仍只有只读 health/list；正式 Client 是上下文、连接状态和内存草稿。历史 Desktop 安装记录为 0.0.12，本计划不表示已经升级。保存服务、路由、Client 适配及大部分业务候选已经存在，但未挂载。

| 已有代码 | 下一步处理 |
|---|---|
| `notebook-schema.js`、`snapshot-budget.js` | 继续作为共享校验和容量入口；修复与 PRD 不一致的边界，不重建模型 |
| `snapshot-coordinator.js` | 所有修改进入同一实例的队列；保留 epoch/revision、持久收据和未知提交停写 |
| `manual-notebook-service.js`、`host/preview-routes.js` | 接入宿主专属 Domain 和正式 Host 生命周期，再按已有层次扩展其余笔记操作 |
| `client/preview-api.js`、`client/manual-save-controller.js` | 接入正式 Client；先修超时悬挂、明确失败和冲突的恢复操作 |
| `note-domain.js`、`tag-domain.js` | 复用候选变换，接入 Service/RPC/UI，不新增第二套业务状态 |
| `query.js`、`markdown-export.js`、`json-backup.js` | 补需求遗漏，再接列表和文件入口 |
| `client/selection-draft.js`、`quote.js`、`text-anchor.js` | 接可信消息适配与 DOM Range，不把调用者布尔标记当来源证明 |

实现链路保持：Client → 宿主 RPC carrier → 精确 Notebook handler → Service → 单一 Snapshot 协调器 → Notebook 专属元数据和 data 文件适配器。Client 列表缓存只是显示用派生状态；正式 Host 使用一个权威文件库。旧 Storage Domain 实验保留为隔离测试，不能与正式文件库并行写入。

继续使用当前 ESM JavaScript 和 `node:test`。本轮不为统一目录或迁移 TypeScript 重写已有模块，不新增框架。确需新增模块时，每个模块必须服务于本计划中的一个完整流程。

## 3. 开发批次：每批交付可操作结果

下面是执行顺序，不是并行基础设施清单。各批先完成源码、定向回归和隔离往返；真实 Desktop 验收按已有授权安排，不让等待实机阻断无依赖源码工作。最终发布必须有真实验收结果。

### A. 手工保存闭环：立即推进

1. 接入专属元数据/data 文件适配器。元数据是唯一提交点；新 data 先同步，元数据替换成功后发布内存状态，回收旧引用；打开坏库时禁止清理或初始化。保持进程内单所有者，不宣称跨进程锁。
2. 区分“库确实不存在”和读取/解析失败。仅前者初始化完整 Snapshot 和稳定默认标签；其余情况停写，保留原数据。
3. Host 拥有 Domain、协调器、Service 和路由；卸载先拒绝新写、排空已接收修改，再按宿主合同关闭资源。
4. 接入新增、列表、详情、标题/正文编辑、安全预览和返回；更新成功后刷新显示数据和版本。
5. 超时必须结束 Client 等待，即使传输不响应 abort；保留草稿与原请求 ID。丢失响应不能解释为未提交；同意图重试使用同一收据。
6. 版本冲突显示冲突并提供读取最新状态后的明确处理，不反复提交已知过期 revision，不静默覆盖草稿。
7. 保护未保存草稿：自有关闭、宿主面板关闭和上下文切换均按受支持能力处理；不能保护的路径必须在接入前解决。
8. 接入 JSON 文件导出，保留现有复制草稿能力。

验收：创建含代码、链接、任务列表和 emoji 的笔记；列表和详情一致；编辑成功；失败保草稿；快速重复点击不重复创建；刷新和重启内容一致。写路由必须通过宿主公开 admission。首版限定单 Desktop 实例，不支持多进程共写同一库。

### B. 摘录与高亮：紧接保存闭环

1. 实现目标版本正文适配，验证两个选区端点属于同一可识别正文，冻结 sessionId、原文和上下文；不从 DOM 伪造官方 messageId 或角色。
2. 接入选择浮层、无标签划线、快捷标签、补充笔记与原文改写；创建和新标签必须一次整体提交。
3. 最小选区按 PRD 的两个非空白 Unicode 码点判断；8000 码点上限保留原选区，不截断。
4. 接消息级文本索引、Anchor 定位和 CSS Highlight；持久化成功后显示持久高亮，失败不留假记录。
5. 接高亮点击详情及列表定位。重复或重叠候选不自动取第一个；未加载消息提示未加载，不宣称已定位。

验收：跨加粗、行内代码、段落、列表和代码块；重复句子、同句跨消息、虚拟化重新挂载、切会话、刷新、卸载。消息身份接缝不明时，只暂停依赖它的摘录；继续其余业务开发，不扩展无关实验。

### C. 笔记库与日常管理

1. 接全部/会话/工作区列表、搜索、类型和标签筛选、时间范围、仅回收站视图及分页。搜索复用已有查询能力；本轮不补来源状态筛选、扩展搜索字段和搜索结果匹配词高亮。
2. 接标签管理，重命名先 trim，规范键与新建一致；合并和删除展示影响数，一次整体提交。
3. 接单条/批量删除、回收站恢复和永久删除；删除不影响来源会话。卡片类型转换入口按 0.0.18 界面决定移出本轮。
4. “会话顺序”按已确认的会话最近活动时间倒序，组内按笔记更新时间倒序；读取目标 SDK 的活动时间投影，不用 sessionId 字典序代替。无法读取活动时间的情况按单独确认的规则处理。
5. 接批量选择、隐藏已选数量和全选查询结果，导出沿确定列表顺序。
6. 接来源打开、归档处理和最新输入草稿追加/替换确认；无能力时保留复制和来源信息，按 PRD 降级。

验收：跨会话查询、组合筛选、时间边界、标签冲突及合并、回收站隔离、筛选后选择、来源删除/归档、不覆盖最新输入。只测相关真实行为，不为每个组件细节增加重复测试。

### D. 文件与最终可靠性收尾

1. Markdown 补导出时间、数量、会话标题、来源、时区及内容开关；保持准确正文、引用和围栏。
2. JSON 完整备份包含全部笔记、回收站、标签、设置、来源和锚点；校验文件读入前限额。
3. 完成 FR-104A：严格校验 → 替换影响预览 → 二次确认 → 重新检查 revision → 保护旧库/原始坏介质 → 同队列整体提交 → 新 epoch → 页面刷新。
4. 保护失败禁止替换；取消、非法文件或提交失败保留旧库/坏原件。提交结果未知停写，不声称回滚。恢复前旧请求必须被拒绝。
5. 只建立当前格式版本检查和后续迁移入口；没有真实旧业务版本时不编造迁移器。将来增加版本必须实现对应迁移和恢复点。
6. 验证输入限额及超限拒绝行为，不裁剪、不自动换数据库。公开实际限制；容量规模与响应时间专项验收暂缓。

本次简化版交付 A/B/C 与 JSON 备份导出。用户已将应用内坏库替换恢复暂缓；D 保留为后续计划，不阻断简化版开放保存，也不宣称 D 已完成。

## 4. 消息定位与高亮：采用参考实现，局部补强

参考 [iptton-ai/dsh-plugin-session-notes 的 Client](https://github.com/iptton-ai/dsh-plugin-session-notes/blob/main/lib/client.js)。2026-10-05 已读取 main 的源码；main 可变，实际抽取时固定 commit 并记录来源。本轮固定提交 raw URL 未成功读取，不把旧指南的提交号称为本轮已复验版本。参考算法，不继承其通信和存储实现；复制代码或实质性片段时保留 MIT 版权与许可声明。

采用的具体思路：

- `collectTextNodes`、`gapBetween`：拼接文本节点，处理块边界与 `<br>`。
- `foldWs` 的偏移映射：搜索文本与 DOM 节点偏移之间转换。
- Range 构造和 CSS Highlight：绘制高亮，避免修改 React 管理的文本节点。
- MutationObserver 合并触发重新协调，Range 滚动定位和 rect 命中作为交互起点。

必须补强的边界：

| 参考实现的简化 | 第一版实现 |
|---|---|
| 扫描会话容器，不确认具体消息端点 | 先经受支持的消息接缝取得身份，只在对应正文根节点建索引；容器发现不等于消息身份验证 |
| 保存前折叠选区空白 | 原始选区准确保存；折叠仅用于派生匹配，不改变 Quote，也不冒充 Markdown |
| `indexOf` 首次命中 | 先校验原偏移，再用 exact/context 消歧；多个候选不猜；不得跨消息兜底 |
| 旧偏移仍匹配 exact 就使用 | 来源文本已变化时同时核对上下文；没有可验证快照不能把旧偏移称为已验证位置 |
| 不支持 CSS Highlight 时包装 `<mark>` | 不侵入消息 DOM；保留列表入口并说明高亮能力不可用 |
| 固定 5 秒全量检查 | 消息挂载/变化时合并协调；仅有当前消息笔记时工作，避免空库周期扫描 |
| 仅凭 Range rect 点击 | 排除插件 UI、已有选区、遮挡和交互目标；重叠候选供选择 |

首版使用明确版本绑定的正文 DOM 边界与文本锚点，不把 DOM class、数组下标或文本搜索结果当官方 messageId。多匹配提示歧义；未加载正文保留笔记并提示不可定位。官方消息身份与原始 Markdown 映射作为后续增强。

最小测试集合：块/inline 拼接、准确空白、Range 边界、相同文本跨消息、同消息重复引用、变化后旧偏移、未加载/已删除来源、observer 合并、点击遮挡和两轮卸载。模拟测试后还须 Desktop 真正选区与重新挂载验收。

## 5. 可靠性做到什么程度

必须保留：标准输入校验、准确引用、单 Host 全修改串行、候选隔离、成功后发布、版本冲突、持久幂等、失败保草稿、未知提交停写、损坏不空库覆盖、JSON 备份；应用内坏库恢复由用户确认暂缓。

本轮停止新增：自建 backend、自有锁文件、worker 生命周期、SQLite、分布式事务、共享介质故障接管、超大库专项。已有实验保留为历史证据，不加入生产包；失败结果不改写为通过。首版实际使用限制为单 Desktop 实例；跨进程共享同一库不受支持，后续另行实现排他保证。

通信继续使用宿主 carrier 和精确 Notebook 路由。扩展写路由前核对 Host/Client/模拟器/实际 Desktop 的版本合同和认证；禁止共享 `/api` interceptor、泛匹配抢占或 global fetch 绕过 carrier。所有资源由宿主生命周期持有，Client 请求支持取消、实际超时和卸载后迟到响应保护。

## 6. 准出与进度记录

每批进度只记录：完整流程、正式入口是否接入、测试结果、Desktop 结果、剩余阻塞。纯函数完成不算对应产品功能完成。不得用测试数量、文档数量或自动运行轮数当产品进度。

每次代码修改运行项目要求：

```bash
npm run check
npm test
npm run pack:check
git diff --check
```

涉及 Domain/生命周期运行 `npm run test:runtime`；涉及业务路由/Client 运行 `npm run test:integration`。check 目前是语法检查，不称类型检查或编译。维护必要失败分支，不不断扩大无关专项。

按本轮已确认范围，简化版 Desktop 发布必须通过（暂缓项见 §1）：

1. A–C 与 D 的 Markdown/JSON 导出实际接入，核心流程可操作；已复现的选区下限、标签 trim、超时、时间筛选和导出遗漏已修复。
2. Desktop 保存、编辑、刷新、重启读回，跨会话列表、摘录高亮和来源定位通过。

4. Markdown 文件可独立阅读；JSON 备份完整包含回收站等数据。应用内受控整库恢复尚未开放，不把预览或候选代码计为通过。
