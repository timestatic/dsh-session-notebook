# 第一版 Desktop 统一验收清单

更新：2026-10-06。0.0.16 已接入专属元数据加 data 文件存储和文本锚点。以下清单待用户实机执行，不能作为已安装或实机通过的声明。

## 执行前置条件

1. 首版使用单 Desktop 实例，不让多个进程写同一 Notebook 目录。
2. 文件适配器已经接入正式 Host；应用内坏库恢复和多进程共享暂缓。
3. 文本锚点记录会话、原文和上下文，不提供官方 messageId。含额外 JSON 块的用户消息暂时保守拒绝选区。
4. 安装/启用/重启按用户授权由官方管理器执行，记录 application/warnings 与实际显示版本。
5. 先使用隔离 synthetic 数据与专属测试介质，避免用用户笔记做失败/损坏注入。

用户已确认采用轻量文件存储和文本锚点，撤销旧的等待 Storage Domain 决定。完整插件卸载或退出会丢失未保存草稿。旧表格中会话活动排序、应用内坏库恢复不能标记通过。

## 统一测试顺序

| 顺序 | 操作 | 通过条件 |
|---|---|---|
| 1 | 正常启动 Desktop，分时观察官方 POST /api/settings/describe | 启动正常，新的请求均 200；记录 Harness/Notebook 版本 |
| 2 | 首次创建含标题、代码、HTTP(S) 链接、任务列表和 emoji 的手工笔记 | 列表、详情、JSON 中原文一致；保存成功后才清草稿 |
| 3 | 编辑标题与正文，快速重复点击保存，刷新并重启 | 无重复记录；版本正确递增；重开内容一致 |
| 4 | 在受控测试接缝模拟取消、超时、回复丢失与版本冲突 | 草稿和请求 ID 保留；同意图重试不重复提交；冲突需读新状态并明确确认；未知提交停写 |
| 5 | 在已完成 user/assistant 消息选择局部文字，跨加粗、行内代码、段落和代码块 | 两端同一可识别正文容器；会话加文本上下文来源；两个非空白码点下限；8000 码点上限不裁剪；准确引用只读 |
| 6 | 保存划线、默认快捷标签、补充笔记和改写；新建标签同时保存 | 持久化成功才显示高亮；新标签与笔记一次整体提交 |
| 7 | 测重复文本、重叠高亮、虚拟化重挂载、切会话和遮挡点击 | 歧义不猜；重叠供选择；重挂载恢复；插件 UI/链接/按钮/已有选区不触发详情 |
| 8 | 组合搜索/类型/标签 AND/OR/无标签/时间/会话/工作区筛选，分页和批量选择 | 稳定分页；隐藏选择数正确；会话活动排序的数据缺口仍暂缓，不能标记通过 |
| 9 | 标签重命名/合并/删除、回收站恢复和永久删除 | 高风险操作影响确认；保留身份和来源；删除不改来源会话；删除默认标签不自动重建；类型转换已移出本轮界面 |
| 10 | 打开来源、确认解除归档、复制 Markdown、追加/替换最新输入草稿 | 来源不可用仍保留快照；不覆盖刚变化的草稿；不自动发送 |
| 11 | 按确定列表顺序导出 Markdown 与完整 JSON | 独立文件可读；时间、数量、来源及选项正确；包括回收站、标签、设置、来源和锚点 |
| 12 | 合法/非法/超限 JSON 导入预览与取消 | 预览统计与有效文件容量正确；取消不写入；应用内坏库替换暂缓，不在用户介质做损坏注入 |
| 13 | 授权后禁用/启用，检查官方 Gateway、认证与本插件资源释放 | Gateway 不受影响；未认证访问拒绝；本插件路由/监听器释放且无重复，恢复原状态 |

性能数值、快捷标签设置/最近使用、来源状态筛选、扩展搜索字段、匹配词高亮与独立 Web 均沿用本轮暂缓范围，不标记为通过。

## 当前可重复本地验证

`npm run check`、`npm test`、`npm run test:integration`、`npm run test:runtime`、`npm run test:mvp-manual`、`npm run pack:check`、`git diff --check`。

`test:integration` 用正式 Host 验证文件保存、重开、鉴权和损坏停写。`test:runtime` 用真实 Cordis Context 验证正式 Host 两轮加载和卸载。它们不证明真实 Desktop carrier、浏览器绘制或交互已通过。
