## 1. 产品概述

### 1.1 产品定义

DSH AI 会话笔记本是一款面向 AI Agent 对话的本地笔记插件。用户可以像阅读电子书一样，对 DSH 会话中的文字进行划线、引用和记笔记，并通过标签、搜索、来源筛选和 Markdown 导出，将散落在不同 AI 会话中的重要内容整理成可长期回顾的个人笔记库。

产品首先解决“如何从 AI 对话中低成本地摘录和沉淀知识”，不承担会话工作流、项目管理或完整任务管理职责。

### 1.2 名称选择

已确定采用：

```text
中文名：DSH AI 会话笔记本
英文名：DSH Session Notebook
包名：dsh-session-notebook
```

选择理由：

1. **Session 与 DSH 领域术语一致**：DSH 使用 Session 表示一次会话，技术含义比 Dialogue 更准确。
2. **Notebook 强调长期积累和组织**：产品不仅保存单条便签，还包括标签、搜索、来源回链与导出。
3. **弱化任务管理含义**：避免 Conversation Notes & Actions 让用户误以为它是 TODO 或工作流插件。
4. **便于未来扩展**：后续可增加笔记集合、摘要或外部知识导入，而不需要再次更名。

界面中的短名称可使用：

```text
AI 笔记
```

仓库与 npm 包使用以下名称（发布前核对 npm 可用性）：

```text
dsh-session-notebook
```

### 1.3 一句话描述

> 对 AI 会话原文进行划线和笔记，保留 Markdown 与来源上下文，并通过标签、搜索和导出形成个人 AI 对话笔记库。

### 1.4 核心价值

1. **保留上下文**：笔记始终保留产生它的会话、消息和引用原文。
2. **降低记录成本**：选中会话文字后，可一次点击划线或快速加入。
3. **保留原始表达**：在 DSH 能提供消息 Markdown 源文的前提下，引用尽可能保存原始 Markdown，而不是只保存渲染后的纯文本。
4. **统一组织**：所有笔记全局可见，可按当前会话、项目工作区、标签、时间和关键词筛选。
5. **便于迁移**：笔记可以导出为可阅读、可长期保存的 Markdown 文件。
6. **本地优先**：默认保存在本机 DSH 插件存储中，不依赖第三方云服务。
7. **来源失效时仍可读**：会话归档或删除不会删除笔记，引用快照始终作为兜底内容保留。

## 2. 背景与问题

AI Agent 会话中包含大量值得长期保存的信息，例如：

- Agent 提出的架构原则；
- 对一段代码或方案的解释；
- 需求分析中的重要结论；
- 用户对 AI 回答的质疑和补充；
- 后续需要验证的技术观点；
- 可复用的命令、代码片段和提示词；
- 某次排障过程中形成的关键判断。

现有做法通常是复制到外部笔记软件，或者依赖会话历史。这些方式存在以下问题：

1. 复制到外部工具后，容易丢失原会话和消息上下文；
2. 手工复制可能丢失 Markdown、代码块、列表和引用结构；
3. 会话数量增加后，很难重新找到曾经看到的重要内容；
4. 普通书签只能收藏整条消息，不能对局部原文做划线；
5. 普通便签缺少原文来源和返回会话的能力；
6. 不同项目中的笔记缺少统一标签和搜索入口；
7. 数据困在插件中时，不利于长期归档和迁移。

## 3. 产品目标与非目标

### 3.1 产品目标

#### G1：建立原文到笔记的最短路径

用户选中会话文字后，可用一次点击完成划线，或快速写下一条笔记。

#### G2：保存可阅读的原文引用

在 DSH 能提供消息源数据时，引用应保留原始 Markdown，包括：

- 标题和段落；
- 加粗、斜体和删除线；
- 行内代码和代码块；
- 列表；
- 引用块；
- 链接；
- 表格。

若无法获得原始 Markdown，插件保存准确的可见纯文本，并明确标记其格式为 `plain_text`，不得把基于 DOM 反推的近似内容冒充为原始 Markdown。

#### G3：保证笔记可追溯

每条从会话产生的笔记均保存：

- 引用内容快照；
- 所属会话 ID 与标题快照；
- 所属项目工作区路径与标题快照；
- 原消息 ID（可获取时）；
- 消息角色；
- 创建时间；
- 用于重新定位的文本锚点。

#### G4：提供完整的标签管理

用户可以创建、选择、重命名、合并和删除标签，并可查看每个标签的笔记数量。

#### G5：支持全局笔记库和来源筛选

所有笔记在全局笔记库中可见。当前会话和项目工作区只是筛选条件，不是笔记的访问范围或隔离边界。

#### G6：支持 Markdown 导出

用户可以将全部笔记或当前筛选结果导出为结构清晰、包含来源信息的 Markdown 文件。

#### G7：可靠保存用户数据

页面刷新、DSH 重启、会话归档或插件升级后笔记不丢失；存储损坏时不得静默覆盖已有数据。

### 3.2 非目标

首个版本不实现：

- 会话工作状态；
- 会话完成、等待、阻塞等工作流；
- 会话级 TODO 进度；
- 会话标签管理；
- 通用任务管理器；
- 日历、看板或甘特图；
- 提醒和重复任务；
- 多人评论线程；
- 多用户权限与实时协同；
- 云端同步；
- 自动执行笔记中的事项；
- 自动将全部历史笔记注入每次模型上下文。

### 3.3 关于 TODO 的产品边界

MVP 不提供独立 TODO 类型、完成状态或任务工作流，但提供内置的 `TODO` 快捷标签。用户可以：

- 选中文字后通过“划线 → TODO”快速保存；
- 在笔记库中筛选 `TODO` 标签；
- 给已有划线或笔记追加/移除 TODO 标签；
- 在笔记正文中使用标准 Markdown 任务列表：

```markdown
- [ ] 补充异常处理
- [x] 完成回归测试
```

`TODO` 的本质是普通标签，不自动产生完成时间、截止日期、优先级或状态机。Markdown 复选框也首先是笔记正文内容。未来如果真实使用数据证明需要结构化任务管理，再作为独立版本评估。

## 4. 目标用户与使用场景

### 4.1 目标用户

1. 使用 DSH 进行开发、代码审查和技术分析的用户；
2. 使用 AI Agent 研究需求、架构或线上问题的技术人员；
3. 需要长期回顾 AI 会话内容的重度用户；
4. 同时维护多个项目工作区和大量会话的用户。

### 4.2 核心使用场景

#### 场景 A：快速划线

用户看到 Agent 给出一段重要的架构原则，选中文字后点击“划线”。原文产生高亮，并进入全局笔记库。记录自动带上当前会话与工作区来源。

#### 场景 B：引用原文并写笔记

用户认为 Agent 的结论遗漏了一个条件，选中文字后点击“记笔记”，输入：

```markdown
这里没有考虑 **refresh token 同时失效** 的情况，需要重新验证。
```

插件保存笔记正文与引用原文。

#### 场景 C：保存 Markdown 代码内容

用户选择包含代码块的回答。插件从消息源数据中取得对应 Markdown 片段，并在笔记详情与导出文件中保留围栏代码块、语言标记和缩进。

#### 场景 D：使用标签整理笔记

用户给笔记添加：

```text
#认证 #架构 #待验证
```

随后在全局笔记库中组合筛选这些标签。

#### 场景 E：按来源筛选

用户在当前项目中打开笔记面板，选择：

```text
当前工作区 + 标签 #架构
```

面板展示该工作区内所有会话产生的匹配笔记。

#### 场景 F：返回来源

用户点击一条历史笔记的“查看来源”，插件打开原会话，滚动到原消息，并尽可能定位到引用文字。

#### 场景 G：从归档会话找回内容

原会话已被 DSH 归档。笔记仍然存在，用户可以从笔记库打开归档会话，或根据 DSH 能力选择恢复后打开。

#### 场景 H：导出 Markdown

用户按工作区和标签筛选笔记，然后将筛选结果导出为 Markdown，用于 Git 仓库、其他笔记软件或长期备份。

## 5. 产品概念与领域对象

### 5.1 引用（Quote）

从会话消息中选择并保存的原文快照。引用是笔记上下文的一部分，不是单独的评论对象。

引用内容采用以下原则：

1. 原始 Markdown 可获得时，保存原始 Markdown 片段；
2. 原始 Markdown 不可获得时，保存用户实际选择的可见纯文本；
3. 记录明确的 `format`，区分 `markdown` 和 `plain_text`；
4. 不持久化 `normalizedText`；
5. 文本匹配所需的折叠空白、大小写或 Unicode 规范化只在定位算法运行时临时计算，不作为引用正文保存；
6. 为重新定位原文，引用之外另存 Text Anchor，不污染可阅读的引用内容。

### 5.2 笔记（Note）

笔记是插件的核心记录对象，分为：

- `highlight`：保存划线引用，可以关联一个或多个标签，但没有用户编写的正文；
- `note`：保留只读原文引用，并附带用户独立编写的 Markdown 笔记正文，用于解释、质疑或补充原文；
- `manual`：用户自主编辑的笔记，既可以从空白开始，也可以将选中原文复制为初稿，修改、重组或提炼后保存。

`manual` 包含两种创建方式，但不增加新的笔记类型：

1. **空白创建**：在笔记面板点击“新建笔记”，没有原文引用；
2. **基于原文改写**：以选中原文作为可编辑初稿，并独立保留只读原始引用和来源。

`note` 与基于原文创建的 `manual` 的区别：

- `note` 是“原文 + 我的补充”，正文默认从空白开始；
- `manual` 改写模式是“将原文加工成自己的笔记”，正文默认由原文副本初始化；
- 用户修改的是 `bodyMarkdown`，不是 AI 消息或原始 Quote；
- 导出时可以同时包含改写内容和原文引用，明确区分“我的改写”和“原始内容”。

持久化的 `note` 必须同时有非空引用和非空正文；正文是否非空按去除首尾空白后的文本判断，但保存原始 Markdown 字符串，不裁剪内容。编辑草稿允许空正文，不属于已保存笔记。

`highlight` 可进入编辑草稿并在保存非空正文成功后转为 `note`，也可复制原文到正文后保存为 `manual`；取消、校验失败或写入失败时保留原 highlight。已有 note/manual 的正文清空后不得直接保存：有引用时可明确确认退回 highlight，无引用的 manual 必须补写正文或执行删除。退回 highlight 必须确认移除原正文；空白创建且无引用的 manual 不可转为划线。

### 5.3 标签（Tag）

标签用于组织笔记。标签属于全局字典，而不是当前会话或工作区的私有对象。

标签至少包含：

- 稳定 ID；
- 显示名称；
- 规范化名称键，用于去重；
- 可选颜色；
- 创建和更新时间。

标签可关联任意笔记，并支持全局重命名、合并与删除。

### 5.4 来源（Source）

来源描述笔记最初来自哪里，包括：

- 会话 ID 和标题快照；
- 消息 ID 和角色；
- 项目工作区路径和标题快照；
- 创建时的 DSH 来源信息。

来源用于筛选和回链，不决定笔记是否可见。

### 5.5 文本锚点（Text Anchor）

文本锚点用于在重新打开会话时定位原文，不作为用户可编辑内容。它可以包含：

- 选中的可见精确文本 `exact`；
- 选区前文 `prefix`；
- 选区后文 `suffix`；
- 消息内开始和结束偏移；
- 相同文本在消息中的出现序号；
- 可选 Markdown 源文中的开始和结束偏移。

定位算法可以临时规范化文本，但锚点中保留的是创建笔记时的真实快照。

### 5.6 可见性与筛选

所有笔记全局可见，不设置 `session/workspace/global` 三种作用域，也不在数据模型中保存 `scope`。

以下仅是查询筛选器：

- 当前会话；
- 当前项目工作区；
- 全部笔记；
- 无会话来源的手工笔记；
- 来源已归档；
- 来源不可用；
- 标签；
- 时间；
- 关键词。

这意味着用户在任意 DSH 会话中都能切换到“全部笔记”，不会因为创建时所在会话不同而看不到某条记录。

### 5.7 来源会话生命周期

DSH 会话生命周期与笔记生命周期相互独立：

- 会话活跃：可正常回链；
- 会话归档：笔记仍可见，并尝试打开归档会话；
- 会话删除：笔记和引用快照仍保留，但来源标记为不可用；
- 笔记删除：不得改变 DSH 会话状态。

核心原则：

> 归档不打断回链，删除会话不删除笔记；来源不可用时，以引用快照兜底。

## 6. 功能需求

### 6.1 文字选区与快捷操作

#### FR-001 选区识别

用户在 DSH 会话消息中选择非空文字时，插件识别选区并显示悬浮操作条。

支持范围：

- 用户消息；
- Assistant 消息；
- Markdown 普通文本、标题、加粗、斜体、链接和行内代码；
- 跨行和跨段落文字；
- 代码块、列表、引用块和表格，前提是能够可靠取得源 Markdown 或准确纯文本。

约束：

- MVP 不允许一个引用跨越多条消息；
- 输入框、插件 UI 和非会话区域选区不触发；
- 少于 2 个有效字符的选区不触发；
- 最大引用长度可配置，MVP 默认 8,000 个 Unicode 码点；至少 2 个有效字符指至少 2 个非空白 Unicode 码点；
- 超限时显示当前长度与上限，阻止划线及加入/改写保存，保留用户选区供缩短；不得静默截断；Host 同样校验最终 Quote 内容长度，原始 Markdown 片段因标记更长而超限时也明确提示，不擅自改成纯文本绕过上限；
- 获取 Markdown 失败不得阻止用户记笔记，应降级为纯文本引用。

#### FR-002 悬浮操作条

选区附近显示：

```text
[划线 ▾] [记笔记 ▾]
```

一级行为：

- 点击“划线”主体：直接保存无标签划线；
- 点击“划线”的下拉区域：打开快速标签二级菜单；
- 点击“记笔记”主体：打开空白正文的笔记编辑器；
- 点击“记笔记”的下拉区域：选择“加入”或“基于原文改写”；
- 点击外部或按 Esc 关闭；
- 窗口边缘处自动调整位置；
- 保存完成后浏览器选区可清除，但插件高亮保留。

#### FR-003 划线快速标签

划线的二级菜单允许用户在不打开完整编辑器的情况下，给新划线快速附加标签：

```text
划线
├── 无标签划线
├── TODO
├── 重要
├── 待验证
├── 最近使用的标签…
└── 选择/新建标签…
```

规则：

- `TODO` 是预置的普通标签，不是结构化任务状态；
- 选择 `TODO` 后创建 `highlight`，并关联 TODO Tag ID；
- TODO 标签笔记可通过标签筛选集中查看，但没有完成时间、截止日期或任务状态机；
- 用户可以像管理其他标签一样重命名或隐藏预置标签；删除预置标签前需要确认；
- 二级菜单优先展示固定快捷标签和最近使用标签；
- “选择/新建标签”打开轻量标签选择器，支持多选；
- 快速创建的新标签进入全局标签字典；
- 用户可在设置中调整快捷标签列表和顺序；
- 点击快捷标签后立即保存，不再打开笔记编辑器。

#### FR-004 记笔记模式

“记笔记”的二级菜单提供：

```text
记笔记
├── 加入
└── 基于原文改写
```

- **加入**：引用保持只读，`bodyMarkdown` 从空白开始；
- **基于原文改写**：引用保持只读，`bodyMarkdown` 使用 Quote 内容副本初始化，用户可以自由修改；
- 如果 Quote 格式为 `plain_text`，改写正文按纯文本初始化到 Markdown 编辑器；
- 改写正文与原始 Quote 分开保存；
- UI 必须明确区分“原始引用”和“我的改写”，避免误认为用户编辑了来源记录。

#### FR-005 整条消息收藏

在消息操作区提供“保存到笔记本”入口，用于不选择局部文字时保存整条消息的 Markdown 内容。

优先级：P1。

### 6.2 Markdown 引用保真

#### FR-010 Markdown 源内容获取

插件优先从 DSH 消息数据模型或会话日志中取得原始消息 Markdown，不以渲染后的 HTML 作为唯一来源。

建议流程：

```text
DOM 选区
→ 确认所属消息 ID
→ 取得消息原始 Markdown
→ 建立渲染文本与 Markdown 源文映射
→ 截取对应 Markdown 片段
→ 保存 Quote
```

#### FR-011 格式降级

引用格式字段：

```ts
type QuoteFormat = 'markdown' | 'plain_text'
```

处理规则：

- 精确 Markdown 片段可取得：保存为 `markdown`；
- 无法可靠映射：保存准确的可见纯文本，标记为 `plain_text`；
- 不允许为了看似美观而生成无法证明等价的“伪原始 Markdown”；
- UI 应允许用户看到引用保存格式。

#### FR-012 Markdown 内容安全

预览引用和笔记正文时：

- 使用受控 Markdown 渲染器；
- 禁止执行原始 HTML 脚本；
- 对链接协议做白名单处理；
- 代码块只作为文本显示；
- 导出时保留 Markdown 源文，不导出渲染后的 HTML。

#### FR-013 Markdown 与定位解耦

引用正文用于阅读和导出，Text Anchor 用于回到页面定位。不得通过修改 Markdown 引用内容来适配高亮算法。

---

### 6.3 原文高亮

#### FR-020 持久高亮

保存划线或笔记后，引用原文产生持久高亮。页面刷新、会话切换和消息重新渲染后应尽可能恢复。

#### FR-021 高亮样式

建议：

- 只有划线：黄色背景；
- 带正文的笔记：黄色背景加侧边标记或笔记图标；
- 当前选中的笔记：增强轮廓；

颜色不是唯一表达方式，应同时使用图标、边框或悬停提示。

#### FR-022 点击高亮

点击高亮原文，打开笔记详情，展示：

- Markdown 引用；
- 笔记正文；
- 标签；
- 来源；
- 创建和更新时间；
- 编辑、查看来源和删除操作。

#### FR-023 高亮恢复降级

无法精确定位时：

- 不删除笔记；
- 仍展示 Markdown 或纯文本引用快照；
- 标记“暂时无法定位原文”；
- 允许打开原消息或原会话；
- 不将定位失败处理成数据丢失。

---

### 6.4 笔记创建与编辑

#### FR-030 加入笔记

选择“加入”后，编辑器展示只读引用预览，并允许用户从空白正文开始输入 Markdown。

字段：

- 笔记正文；
- 标签；
- 来源信息，只读；
- 引用内容，只读；
- 引用格式，只读。

编辑器采用 Markdown 文本编辑 + 预览切换，不提供所见即所得。必须填写非空正文才能保存为 `note`，引用同时必须非空；空正文点击保存提示“请填写笔记正文”，保留草稿，不自动降为 highlight。取消、离开或关闭有未保存修改的编辑器须确认；持久化失败保留编辑内容并允许重试。

#### FR-031 基于原文改写

用户可以选择“基于原文改写”：

1. 插件保留原始 `QuoteSnapshot`；
2. 将 Quote 内容复制到 `bodyMarkdown` 作为可编辑初稿；
3. 用户可以改写措辞、删除冗余、重组结构或提炼结论；
4. 保存后记录类型为 `manual`，界面标记为“基于原文改写”；
5. 原始引用、Text Anchor 和 Source 保持不变；
6. 后续编辑只修改改写正文，不修改来源快照。

详情页同时展示：

```text
我的改写
原始引用
来源
```

导出时默认同时包含“我的改写”和“原文引用”，用户可以在导出选项中关闭原文引用。

#### FR-032 手工笔记

用户可以在右侧面板中创建不关联引用的手工笔记。手工笔记从空白正文开始，仍然全局可见，并可记录创建时所在会话和工作区作为可选上下文。

`manual` 支持空白创建和基于原文改写两种方式：

- 空白创建没有 Quote 和 Text Anchor，可记录当前会话或工作区作为上下文；
- 基于原文改写保留原始 Quote、Source 和可获得的 Text Anchor；
- 空白笔记没有精确原文回链；
- 基于原文改写的笔记可以返回原消息，并在锚点可用时定位原文；
- 两种方式使用同一类型和编辑器，不建立额外的改写笔记系统。

#### FR-033 编辑笔记

允许修改：

- 笔记正文或改写正文；
- 标签；
- 标题，可选；

引用原文始终只读，以保证来源快照可信。用户修改的是自己的正文副本，不覆盖 `QuoteSnapshot.content`。

#### FR-034 从划线转换

用户可以把 `highlight` 转换为：

- `note`：进入空白正文编辑草稿，填写非空正文并持久化成功后才转换；
- `manual`：进入用 Quote 内容初始化的编辑草稿，正文非空并持久化成功后才转换。

转换时保留 ID、引用、标签、来源和创建时间；取消、空正文或写入失败均不改变原记录类型。已有正文清空后仅可明确确认退回 `highlight`，否则不能保存；插件不自动丢弃正文。

#### FR-035 删除笔记

- 支持单条删除和批量删除；
- 单条删除前二次确认，显示笔记标题；批量删除前二次确认，显示数量和笔记列表；
- 取消确认不改变任何笔记；
- 删除后移除原文高亮；
- MVP 普通删除必须进入回收站，不立即物理删除；
- 回收站默认无限期保留，不自动清空；
- 回收站中可恢复；永久删除须再次确认影响数量，取消不修改数据；
- 删除笔记不得影响 DSH 原会话。

### 6.5 标签管理

#### FR-040 创建与选择标签

编辑笔记时支持：

- 输入新标签；
- 从已有标签中选择；
- 关键词搜索标签；
- 多选；
- 显示名称去除首尾空白，保留其余原写法；空名称禁止保存；
- 规范化名称键按 `displayName.normalize('NFKC').trim().toLowerCase()` 生成，使用与 locale 无关的规则，不区分大小写；规范化后仍为空则拒绝；
- 新建、重命名均按此键去重，例如 TODO/todo、Ａ/A 指向同一名称键；内部空白不折叠，重命名冲突提示选择合并，不自动合并；
- 名称长度按去除首尾空白后的显示名 Unicode 码点计数。

默认限制：

- 每条笔记最多 10 个标签；
- 单个标签名称最多 32 个字符。

#### FR-041 预置与快捷标签

插件首次初始化时必须创建以下默认快捷标签，允许用户后续调整或隐藏；用户删除后不得在每次加载时自动重新创建：

- `TODO`：需要后续处理；
- `重要`：值得重点保留；
- `待验证`：结论或方案需要进一步确认。

它们的本质仍是普通 `TagRecord`：

- 不引入任务状态机；
- 可以用于划线快速创建；
- 可以参与搜索、筛选、重命名和合并；
- 可通过 `isBuiltin` 或独立设置记录预置身份；
- 用户可以隐藏某个快捷标签，使其不再出现在选区二级菜单；
- 用户可以将任意普通标签固定到快捷菜单；
- TODO 标签被重命名后，应继续通过 Tag ID 识别，而不是依赖字符串 `TODO`。

#### FR-042 标签列表

标签管理页展示：

- 标签名称；
- 可选颜色；
- 使用该标签的笔记数量；
- 最近使用时间；
- 重命名、合并和删除操作。

#### FR-043 标签重命名

重命名标签后，所有关联笔记自动显示新名称，笔记本身不需要逐条复制更新标签文本。

因此笔记应关联 Tag ID，而不是只保存自由文本数组。

#### FR-044 标签合并

用户可以将标签 A 合并到标签 B：

1. 所有引用 A 的笔记改为引用 B；
2. 同时已有 B 的笔记去重；
3. A 进入删除状态；
4. 操作前显示影响笔记数量；
5. 操作应具备原子性或可回滚性。

#### FR-045 标签删除

删除标签默认只解除其与笔记的关联，不删除任何笔记。删除前显示影响数量并要求确认。

#### FR-046 标签筛选

支持：

- 单标签筛选；
- 多标签“全部匹配”（AND）；
- 多标签“任一匹配”（OR）；
- 无标签笔记；
- 标签与来源、关键词、时间组合筛选。

### 6.6 全局笔记库与来源筛选

#### FR-050 面板入口

通过 DSH 原生右侧栏注册“AI 笔记”Tab；若当前 DSH 版本不提供右侧栏服务，可降级为右侧抽屉。

#### FR-051 一级视图

建议三个一级视图：

1. **当前会话**：当前会话产生的笔记；
2. **笔记库**：全部笔记及组合筛选；
3. **标签**：标签字典和管理。

这些是同一份全局数据的不同视图，不代表不同的存储作用域。

#### FR-052 当前会话视图

展示：

- 当前会话中的划线和笔记；
- 当前会话笔记数量；
- 新建手工笔记；
- 关键词和标签筛选；
- 打开“全部笔记”。

不提供会话状态、会话完成和会话标签。

#### FR-053 笔记库视图

支持来源过滤：

- 当前会话；
- 当前项目工作区；
- 全部；
- 手工笔记；
- 来源会话已归档；
- 来源不可用。

支持内容过滤：

- 只有划线；
- 带正文的笔记；
- 标签；
- 关键词；
- 创建/更新时间；
- 回收站。

#### FR-054 笔记卡片

至少显示：

- 可选标题或正文摘要；
- Markdown 引用摘要；
- 标签；
- 会话和工作区来源；
- 引用格式标识；
- 创建或更新时间；
- 常用操作。

#### FR-055 卡片操作

提供：

- 查看详情；
- 编辑；
- 查看来源；
- 复制 Markdown；
- 写入当前输入框（MVP）：默认追加到最新草稿，不自动发送或唤醒 Agent；存在草稿时先展示追加/替换确认，替换必须由用户选择；
- 删除/恢复。

无当前会话或输入框能力不可用时禁用写入入口并说明原因，保留复制 Markdown 作为替代。

#### FR-056 排序

支持：

- 最近创建；
- 最近更新；
- 会话顺序；
- 工作区；
- 标签。

MVP 默认按最近更新降序。

### 6.7 来源回链与归档会话

#### FR-060 打开原会话

点击“查看来源”后，通过 `sessionId` 打开原会话，而不是只依赖当前会话列表中的可见项。

#### FR-061 归档会话

若来源会话被 DSH 归档：

- 笔记仍显示在全局笔记库；
- 插件查询来源时应包含归档会话；
- DSH 支持直接打开归档会话时，提供“在归档中打开”；
- 若必须恢复才能打开，先提示用户，再执行“恢复并打开”；
- 不得未经确认自动恢复会话。

#### FR-062 定位原消息和引用

来源可用时按以下顺序定位：

1. 打开会话；
2. 定位消息 ID；
3. 滚动到消息；
4. 使用 Text Anchor 定位精确文字；
5. 对引用进行短暂视觉提示。

#### FR-063 来源不可用

会话被删除或暂时无法访问时：

- 保留完整笔记；
- 保留 Markdown 或纯文本引用；
- 显示“来源会话不可用”；
- 允许复制来源 ID 与引用内容；
- 允许稍后重试；
- 不自动删除笔记。

#### FR-064 回链降级顺序

```text
精确引用 → 原消息 → 原会话 → 本地引用快照
```

任何降级都不得导致笔记不可读。

### 6.8 搜索

#### FR-070 全文搜索

搜索范围：

- 笔记标题；
- 笔记 Markdown 正文；
- 引用 Markdown 或纯文本；
- 会话标题快照；
- 工作区标题和路径；
- 标签名称。

MVP 可采用本地内存搜索；数据量增长后再增加持久索引。

#### FR-071 搜索与筛选组合

关键词可与以下条件组合：

- 当前会话；
- 当前工作区；
- 标签；
- 记录类型；
- 时间；
- 来源状态。

#### FR-072 搜索结果高亮

搜索结果中突出匹配词，但不得修改保存的 Markdown 源内容。

### 6.9 Markdown 导出

#### FR-080 导出入口与选择

笔记库支持多选模式。用户可以：

- 勾选一条或多条笔记；
- 一键全选当前筛选结果；
- 取消选择；
- 查看已选择数量；
- 点击“导出 Markdown”。

单条笔记也可以从卡片菜单直接导出。

#### FR-081 导出范围

导出范围以用户当前勾选的笔记为准。为提高效率，可以提供快捷选择：

- 当前会话全部笔记；
- 当前项目工作区全部笔记；
- 当前筛选结果；
- 指定标签下的全部笔记；
- 全部笔记。

快捷选择只负责批量勾选，用户仍可在导出前增删具体笔记。

#### FR-082 导出文件

一次导出生成一个 UTF-8 `.md` 文件，不生成目录、ZIP、索引页或同步清单。

文件名示例：

```text
dsh-session-notebook-2026-10-02.md
project-auth-notes-2026-10-02.md
```

#### FR-083 Markdown 结构

默认导出格式：

```markdown
# DSH AI 会话笔记

> 导出时间：2026-10-02 11:30 +08:00
> 笔记数量：2

---

## 补充 token 过期处理

- 标签：`认证`、`待验证`
- 会话：登录接口重构
- 工作区：`/path/to/my-project`
- 创建时间：2026-10-01 15:30 +08:00

### 笔记

这里没有考虑 **refresh token 同时失效** 的情况。

### 原文引用

> 当前实现没有处理 refresh token 失效后的降级逻辑。
```

多条笔记之间使用分隔线分开。笔记顺序默认与当前列表排序一致。

#### FR-084 Markdown 保真导出

- 引用格式为 `markdown` 时，尽可能原样输出其 Markdown；
- 引用格式为 `plain_text` 时，进行安全的 Markdown 引用或围栏处理，避免破坏文档结构；
- 笔记正文按用户保存的 Markdown 输出；
- 代码围栏冲突时自动选择更长围栏；
- 不将渲染后的 HTML 写入导出文件；
- 文件统一使用 UTF-8；
- 导出的标准 Markdown 应能被 Obsidian、Typora、VS Code 和常见 Markdown 阅读器直接打开。

#### FR-085 导出内容选项

导出前提供少量选项：

- 是否包含标签；
- 是否包含会话和工作区来源；
- 是否包含 Session ID 和 Message ID；
- 是否包含创建和更新时间；
- 是否包含原文引用。

MVP 默认全部包含，用户可取消不需要的元数据。避免引入模板系统和复杂格式配置。

#### FR-086 来源链接

若 DSH 支持稳定的会话 Deep Link，可以在来源信息中写入链接；否则写入普通文本：

- 会话标题；
- Session ID；
- Message ID；
- 工作区路径。

导出文件必须脱离 DSH 仍然可阅读，不能依赖 Obsidian 专属语法或第三方插件。

#### FR-087 JSON 备份

除 Markdown 阅读导出外，提供 JSON 完整备份，用于恢复所有内部字段、标签关系和 Text Anchor。Markdown 导出不是完整数据备份的替代品。

### 6.10 数据存储与可靠性

#### FR-100 本地持久化

**已确定方案：DSH 自带存储服务 + 结构化数据，正文保存 Markdown 字符串。**

- 使用 DSH Storage Domain，在插件独立命名空间中保存笔记、标签及必要设置；
- Host 统一读取、校验和持久化，浏览器面板不直接修改底层文件；
- `bodyMarkdown` 保存用户正文，`quote.content` 保存原始引用，引用格式仍区分 `markdown` 和 `plain_text`；
- 来源、文本锚点、标签关联、时间、删除状态和版本作为结构化字段保存；
- 用户改写正文不得覆盖原始引用；
- 所有笔记使用同一份全局笔记库，会话和工作区仅作为筛选条件；
- 不依赖第三方云服务。

Markdown 是内容与导出格式，不是主存储载体。MVP 不引入独立 SQLite、逐条 Markdown 文件存储或数据库与文件双写。

Storage Domain 的物理文件位置和底层实现由 DSH 管理，插件不假定固定路径，也不把“使用存储服务”等同于已获得事务保证。具体 API 和持久化语义需在 Phase 0 验证。

#### FR-101 Schema 版本

数据必须包含 `schemaVersion`，并提供显式迁移流程。

#### FR-102 安全写入

要求：

- 同一 Host 内的修改统一串行执行；
- 每次修改校验记录版本，冲突时提示刷新或重试，不静默覆盖；
- 修改先生成候选数据，持久化成功后才更新权威缓存并向界面确认保存成功；
- 不使用静默清空作为读取或解析失败的恢复方式；
- 写入失败时保留旧数据和用户尚未保存的编辑内容；
- 标签合并等关联修改必须整体提交，不得出现标签已删除但笔记关联未更新的半完成状态；
- 优先使用经验证的宿主持久化与原子更新能力；如果宿主仅支持单条原子更新，MVP 可将笔记与标签作为一个逻辑快照整体提交；
- 若持久化、并发或整体提交能力无法可靠保证，必须作为发布阻断问题解决，不以普通文件覆盖或跨进程不安全的内存队列代替；
- 多 Host 进程同时写入的支持范围必须明确，不能将单进程串行化误认为跨进程安全。

#### FR-103 损坏处理

检测到损坏数据时：

1. 停止覆盖原数据；
2. 保存损坏副本；
3. 显示错误；
4. 提供 FR-104A 的受控 JSON 整库恢复入口；普通写入保持禁用，恢复路径必须先保护原介质再按该流程整体替换。

#### FR-104 受控恢复与通用导入

**FR-104A 受控 JSON 整库恢复：MVP 必须。**

- 仅接收本插件 FR-087 导出的完整 JSON 备份，包含业务 Schema 版本、全部笔记（含回收站）、标签、设置、来源和完整锚点；不支持部分数据拼接或旧插件数据。
- 文件默认最多 50 MiB，可配置；在读取/解析前限制大小，再严格校验 Schema、字段长度、Tag 关联及版本。受支持旧版本必须先生成迁移候选；未知更高版本拒绝恢复，不修改当前库。
- 预览记录、回收站、标签数量与备份版本，明确“将替换当前整库，不执行增量合并”；用户二次确认才执行，取消不改变数据。
- 提交前创建并校验现有库恢复点；当前介质损坏时保存原始损坏副本，不能解析不代表原始副本可省略。保护副本失败则禁止替换。
- 将完整候选整体提交；失败保留操作前数据或损坏原介质及草稿，不留下半更新。恢复与普通修改共享 Host 队列，并重新校验预览时的 revision/介质状态，状态变化必须重新预览确认。
- 成功后刷新所有连接页面；恢复内容的原始 ID、createdAt、Quote/Anchor/Source 不变，但库提交 revision、并发 token 必须进入新代际，使恢复前的旧客户端写请求被拒绝，不能因版本回退误覆盖恢复结果。
- 无有效备份时只读保留原数据并提示取得备份，不提供自动清空“修复”；恢复不创建或修改 DSH 来源会话。

**FR-104B 通用增量导入与合并：P1，不进入 MVP。**

- 导入本插件部分数据、增量合并；
- Schema 校验与数据预览；
- ID 冲突处理与标签合并策略；
- 失败整体回滚。

兼容 `dsh-plugin-session-notes` 旧数据另属 P1，按 §17.3 评估；不能把它作为 MVP 受控恢复入口默认接受的格式。

#### FR-105 卸载行为

卸载插件默认不删除笔记数据。若用户希望清除数据，必须通过独立、明确确认的操作完成。

#### FR-106 主存储与导出分离

- DSH 存储服务中的结构化记录是唯一权威数据源；
- Markdown 导出只在用户主动操作时生成，不自动回写、不持续同步；
- 用户在外部编辑导出的 Markdown，不影响插件中的笔记；
- JSON 完整备份从同一数据源生成，包含 Schema 版本、笔记、标签及恢复所需设置；
- 浏览器缓存仅用于界面响应，不替代 Host 持久化；
- 不将笔记按项目工作区分别存储，避免切换项目后丢失全局可见性。

#### FR-107 轻量查询与维护

MVP 使用宿主加载的结构化记录，在内存中完成来源筛选、标签筛选、排序和关键词搜索，避免引入独立搜索服务、ORM 或重复维护的磁盘索引。

逻辑数据包括笔记集合、标签集合、Schema 版本和必要设置；具体使用单个快照还是独立记录，由 Phase 0 的宿主 API 验证结果决定。只隔离简单的存储读写接口，不建设通用可插拔数据库框架。

如果实际数据量导致加载、搜索或全量保存无法满足性能标准，或宿主无法满足可靠修改要求，再另行评估 SQLite。更换底层存储不得改变用户使用方式、笔记身份和 Markdown 导出格式，也不得未经批准成为 MVP 的额外依赖。

## 7. 核心交互流程

### 7.1 划线流程

无标签快速划线：

```text
用户选中文字
→ 显示 [划线 ▾] [记笔记 ▾]
→ 点击“划线”主体
→ 尝试提取原始 Markdown
→ 保存无标签 highlight
→ 原文显示高亮
```

带标签快速划线：

```text
用户选中文字
→ 点击“划线 ▾”
→ 选择 TODO / 重要 / 待验证 / 最近标签
→ 保存 highlight 并关联所选 Tag ID
→ 原文显示高亮和标签提示
```

目标：常用标签划线最多两次点击完成，不进入完整编辑器。

### 7.2 加入流程

```text
用户选中文字
→ 点击“记笔记”或选择“加入”
→ 打开空白 Markdown 编辑器
→ 输入自己的补充正文并选择标签
→ 保存为 note
→ 原文显示笔记高亮
```

### 7.3 基于原文改写流程

```text
用户选中文字
→ 点击“记笔记 ▾”
→ 选择“基于原文改写”
→ 将 Quote 副本载入 Markdown 编辑器
→ 用户删改、重组或提炼内容
→ 保存为 manual（基于原文改写）
→ 原始 Quote 继续只读保留
```

### 7.4 标签管理流程

```text
用户打开“标签”视图
→ 查看名称与使用数量
→ 选择重命名 / 合并 / 删除
→ 查看影响范围并确认
→ 原子更新标签关系
→ 当前筛选和卡片同步刷新
```

### 7.5 来源回链流程

```text
用户点击“查看来源”
→ 查询活跃和归档会话
→ 打开或提示恢复归档会话
→ 定位消息
→ 定位精确引用
→ 失败时降级展示本地引用快照
```

### 7.6 Markdown 导出流程

```text
用户在笔记库设置筛选条件
→ 勾选要导出的笔记或全选筛选结果
→ 点击“导出 Markdown”
→ 确认已选择数量及导出内容
→ 合并生成一个 UTF-8 Markdown 文件
→ 下载或保存文件
```

- 保存失败：保留已输入内容，显示“重试”；
- 无选中笔记时，批量导出按钮不可点击。

## 9. 数据模型草案

```ts
export type NoteKind = 'highlight' | 'note' | 'manual'
export type QuoteFormat = 'markdown' | 'plain_text'
export type MessageRole = 'user' | 'assistant' | 'tool' | 'system'
export type SourceSessionState =
  | 'active'
  | 'archived'
  | 'deleted'
  | 'unavailable'
  | 'unknown'

export interface QuoteSnapshot {
  format: QuoteFormat
  content: string
}

export interface TextAnchor {
  // 用户创建笔记时实际选中的可见文本，不做持久化规范化。
  exact: string
  prefix?: string
  suffix?: string

  startOffset?: number
  endOffset?: number
  occurrence?: number

  markdownStartOffset?: number
  markdownEndOffset?: number
}

export interface NoteSource {
  sessionId?: string
  sessionTitle?: string

  messageId?: string
  messageRole?: MessageRole

  workspacePath?: string
  workspaceTitle?: string

  // 最近一次探测到的状态，仅为缓存；打开来源时重新查询。
  sessionState?: SourceSessionState
}

export interface NoteRecord {
  id: string
  schemaVersion: 1

  kind: NoteKind
  title?: string
  bodyMarkdown?: string

  quote?: QuoteSnapshot
  anchor?: TextAnchor
  source?: NoteSource

  tagIds: string[]

  createdBy: 'user' | 'agent'
  createdAt: string
  updatedAt: string

  deletedAt?: string
  version: number
}

export interface TagRecord {
  id: string
  schemaVersion: 1

  name: string
  normalizedKey: string
  color?: string

  // 预置标签仍是普通标签；该字段仅用于默认配置和快捷菜单。
  isBuiltin?: boolean
  isQuickTag?: boolean
  quickTagOrder?: number

  createdAt: string
  updatedAt: string
  deletedAt?: string
  version: number
}
```

### 9.1 模型约束

- `highlight` 必须有非空 `quote`，`bodyMarkdown` 必须缺省或为空字符串，但可以关联标签；
- 持久化 `note` 必须同时有非空 `quote` 和非空 `bodyMarkdown`，正文用于补充或评论原文；编辑草稿可为空，但不得按 note 提交；
- 正文非空以去除首尾空白后仍有字符判断；实际保存保留原始 Markdown 字符串，不做 trim 或静默截断；
- `manual` 必须有非空 `bodyMarkdown`，支持空白创建或基于原文副本初始化；
- 空白创建的 `manual` 可以没有 `quote`、`anchor` 和会话来源；
- 基于原文改写的 `manual` 保留 `quote` 和 `source`，并尽可能保存 `anchor`；
- `note` 和 `manual` 的 `bodyMarkdown` 都可由用户编辑；
- `quote.content` 是不可变的来源快照，用户改写不得覆盖它；
- `anchor` 专门用于页面定位，不替代引用内容；
- 不保存 `normalizedText`；
- 不保存 `scope`；
- 所有笔记全局可查询；
- 当前会话和工作区通过 `source` 字段筛选；
- 笔记通过 `tagIds` 关联标签，以支持全局重命名和合并；
- `sessionState` 不是绝对真相，查看来源时应重新探测；
- DSH 会话归档、删除与笔记删除相互独立。

## 10. DSH 插件实现映射

### 10.1 双端支持与插件组成

**DSH Web 与 DSH 桌面版均为 MVP 必须支持的平台，不将桌面版仅作为后续兼容项。** 两端提供相同的核心能力：选区划线、快捷标签、加入笔记、原文改写、全局笔记库、标签管理、来源回链、单条/批量删除与 Markdown 导出。

```text
一个 npm 包
├── Host 插件：统一校验、存储和笔记服务
├── 共享客户端界面与交互
│   ├── DSH Web：浏览器入口
│   └── DSH 桌面版：桌面客户端入口
├── 双端适配：安装加载、面板、来源打开、文件保存
├── Bundle/Profile 配置（分别验证 Web 和桌面加载）
├── Shared Schemas
├── Markdown 导出器
├── 标签与笔记 Repository
└── 可选 Agent Tools（未来）
```

共享产品逻辑与数据模型，避免分别维护两套笔记实现。桌面客户端是否可以直接复用 Web Client Bundle，必须通过实际 DSH API 和加载验证确认；不预先假定桌面版一定采用相同插件接缝。

双端支持不等于自动同步：全局笔记库指连接到同一 Host 存储实例的全局可见性。若 Web 和桌面使用不同 Host、Profile 存储或设备，不保证自动共享数据，也不引入云同步或自行跨进程读写同一文件。

### 10.2 预期 DSH 接缝

| 需求 | DSH 插件机制 |
|---|---|
| 消息区域定位 | `conversation.composer.dock` 隐藏锚点，向上寻找消息滚动容器 |
| 选区悬浮工具条 | `shell.overlay` 注册浮层 UI |
| 原生右侧栏 | `sidebarRightTabs` + `sidebar.right.pane.tab` |
| 当前会话/工作区 | Slot Props / Workspace Store |
| 获取消息 Markdown | 消息数据服务、会话日志或稳定的消息查询 API |
| 打开活跃/归档会话 | Session Controller/API，查询时包含归档项 |
| 写入当前输入框 | Composer `inputActions.setDraft` |
| Host/Client 通信 | DSH Remote Service 或类型约束 RPC |
| 持久化 | Host 使用 DSH Storage Domain 保存结构化记录，正文为 Markdown 字符串 |
| 文件导出 | 共享 Markdown 生成逻辑；Web 使用浏览器下载，桌面优先使用经验证的宿主保存能力，否则验证可用下载方式 |

以上为待验证的实现候选，不是双端 API 已验证清单。技术验证必须分别确认：

| 能力 | DSH Web | DSH 桌面版 |
|---|---|---|
| 插件安装与加载 | 验证 Web Profile 的 Host 和客户端贡献加载 | 验证桌面安装入口、Profile、Host 和客户端贡献加载 |
| 笔记面板与选区工具条 | 验证浏览器 Slot 与选区行为 | 验证桌面界面对应 Slot、选区与浮层行为 |
| 原始 Markdown 与高亮 | 验证消息数据获取与页面重绘恢复 | 验证相同能力及桌面会话切换、窗口重开后的恢复 |
| 来源回链 | 在当前 Web 客户端打开对应会话 | 在当前桌面客户端打开对应会话，不默认跳转外部浏览器 |
| 持久化 | 通过所连接 Host 的 Storage Domain 读写 | 通过桌面所连接 Host 的 Storage Domain 读写，验证实际隔离边界 |
| 导出与复制 | 浏览器下载与剪贴板权限 | 验证保存/下载与剪贴板能力，不直接假定浏览器行为一致 |
| 安全与兼容 | 不依赖浏览器直接访问本地数据库或文件 | 不依赖未公开的桌面内部模块或默认全盘写权限 |

某端缺少原生右侧栏时可以使用等效抽屉，但不能以降级为由取消该端的核心产品功能。两端都需独立完成安装、保存、重启恢复、删除确认和导出验收。

### 10.3 Markdown 选区映射

“保留原始 Markdown”不能只依赖 DOM Selection，因为浏览器选区通常只能返回可见文本。技术验证阶段必须确认：

1. DSH Client 是否暴露消息 ID；
2. 能否通过消息 ID 读取原始 Markdown；
3. Markdown 渲染器是否提供 source position；
4. 能否从 DOM Range 映射到 Markdown 源偏移；
5. 代码块、链接、列表和表格能否稳定映射。

推荐优先级：

```text
DSH 原生 source position
→ 消息 Markdown + 渲染映射
→ 无法证明原始源片段时保存选中可见纯文本（plain_text）
```

DOM-to-Markdown 转换只能作为未来编辑正文的辅助手段，不能将合成内容标记为原始 Markdown 引用。

```text
禁止：DOM 反推的近似 Markdown → 冒充来源原文
```

不得承诺所有选区都能 100% 还原原始 Markdown。产品承诺应是“尽可能保留原始 Markdown；无法可靠还原时明确降级为纯文本”。

### 10.4 高亮策略

优先使用 CSS Custom Highlight API：

```text
消息级 Text Anchor
→ 收集渲染文本节点
→ 运行时临时建立文本索引
→ 查找 exact/prefix/suffix
→ 创建 Range
→ 注册 Highlight Group
```

运行时可以进行空白折叠和 Unicode 规范化，但这些仅属于匹配算法，不写回 `QuoteSnapshot` 或 `TextAnchor.exact`。

### 10.5 推荐接口

```text
notes.list
notes.get
notes.create
notes.update
notes.restore
notes.trash
notes.deletePermanently
notes.search

 tags.list
 tags.create
 tags.rename
 tags.merge
 tags.delete

 sources.resolve
 exports.markdown
 backups.exportJson
 backups.restoreJson  # MVP 受控整库恢复
backups.importJson   # P1 增量导入与合并
```

接口需要验证：

- Markdown 和引用长度；
- 标签数量；
- 枚举；
- 乐观锁版本；
- 未知字段；
- Schema 版本；
- 导出范围；
- 标签合并目标；
- 导入文件大小和内容安全。

## 11. 非功能需求

### NFR-001 性能

- 无笔记时不周期扫描整场会话；
- 只恢复当前会话相关高亮；
- DOM 变化后防抖协调；
- 面板支持至少 2,000 条笔记的可接受浏览；
- 常规本地搜索输入响应目标小于 150ms；
- Markdown 导出 5,000 条笔记时不得阻塞 UI 到不可操作。

### NFR-002 可靠性

- 写入失败不能造成已有笔记丢失；
- 解析失败不能自动覆盖为空数据；
- 每次数据迁移前创建恢复点；
- 多标签页修改使用版本号防止静默覆盖；
- 标签合并失败不能留下半更新关系；
- 会话删除或归档不能级联删除笔记。

### NFR-003 隐私

- 默认不上传数据；
- 不自动把历史笔记发送给模型；
- 导出操作由用户主动触发；
- 设置页展示本地存储位置和数据用途。

### NFR-004 安全

- 不申请 `danger-full-access` 作为常态权限；
- 优先使用 DSH Storage Domain；
- Markdown 渲染需要防止 HTML/XSS 注入；
- 导入文件进行 Schema、大小和内容验证；
- 导出路径和文件名需安全处理。

### NFR-005 兼容性

- DSH Web 和 DSH 桌面版均为正式支持平台，核心功能一致；
- 分别验证两端的安装、加载、界面、持久化、来源回链、复制和导出，不以一端通过代替另一端验收；
- 声明支持的 DSH 版本；
- Slot 或消息 API 不存在时提供明确降级；
- Markdown 源文不可得时仍能保存纯文本笔记。

### NFR-006 可访问性

- 所有操作支持键盘；
- Esc 关闭浮层；
- 控件提供可读标签；
- 颜色不是唯一状态表达；
- 跟随 DSH 深浅主题。

## 12. MVP 范围

### 12.1 MVP 必须包含

1. 可在 DSH Web 和 DSH 桌面版安装加载，核心笔记功能双端可用；
2. 支持用户和 Assistant 消息文字选择；
3. 无标签划线、快捷标签划线和记笔记；
4. `manual` 支持空白创建和基于原文改写；
5. 尽可能保存原始 Markdown，失败时明确降级为纯文本；
6. CSS Highlight 持久高亮；
7. 右侧“AI 笔记”面板；
8. 所有笔记全局可见；
9. 当前会话、当前工作区、全部三种来源筛选；
10. 标签创建、选择、重命名、合并和删除，以及内置 TODO 快捷标签；
11. 关键词搜索；
12. 打开来源会话；
13. 识别归档会话并支持打开或确认恢复；
14. 尽可能定位原消息和原文；
15. 勾选单条或多条笔记导出为一个标准 Markdown 文件；
16. JSON 完整备份；
17. 单条与批量删除（二次确认）及回收站；
18. 本地可靠持久化；
19. Schema 版本和迁移框架（FR-101/102）；
20. 本插件 JSON 完整备份的受控整库恢复，包括校验、预览、二次确认、保护旧介质、整体提交及失败回滚（FR-104A）；
21. 复制 Markdown 与经用户确认写入当前输入框草稿，绝不自动发送（FR-055）。
22. 标签使用 6 色色板：亮粉色 `#FF5FA2`、活力橙 `#FF7A00`、明黄色 `#FFD000`、薄荷绿 `#00D9A3`、亮蓝色 `#3A86FF`、紫罗兰色 `#7B61FF`。新标签优先分配当前使用最少的颜色；用户可在标签管理中改选。颜色选择只显示色块，名称留作无障碍说明；编辑标签使用带保存和取消操作的弹框。标签页面直接显示颜色，笔记列表和详情按标签颜色显示。旧色板按相近颜色显示为新色板颜色，不改写原有备份。色板用完后允许重复颜色，颜色不单独表示状态。

功能优先级规则：§6 中未单独标为 P1/后续版本的 FR 均为 MVP 必须，适用前提不满足时按对应 FR 的明确降级处理；FR-005、FR-104B 及 §17.3 事项除外。FR-104A 必须实现，不能因 FR-104B 标 P1 而延后恢复功能。

### 12.2 MVP 不包含

- 整条消息收藏（FR-005，P1）；
- Tool 消息摘录；
- 通用增量导入、ID 冲突合并及旧插件迁移（FR-104B，P1；不包括必需的 FR-104A）；
- 结构化 TODO；
- 会话工作状态；
- 会话标签；
- 截止日期和提醒；
- 多级评论线程；
- 子任务；
- 日历、看板和甘特图；
- 云同步；
- 多用户协作；
- Agent Tools；
- MCP；
- 图片附件；
- 自动总结；
- 自动提取行动项；
- 跨设备同步。

## 14. MVP 验收标准

### AC-001 划线

在 Assistant 消息中选择跨加粗节点的文字，点击“划线”，刷新页面后高亮仍能恢复。

### AC-002 Markdown 引用

选择包含加粗、链接或代码的内容：

- 能可靠映射时，保存并导出原始 Markdown；
- 不能可靠映射时，保存准确纯文本并标记 `plain_text`；
- 不生成冒充原始内容的近似 Markdown。

### AC-003 笔记

选择原文并添加 Markdown 笔记，右侧卡片同时显示笔记正文、引用快照和来源。

### AC-004 全局可见

在会话 A 创建的笔记，在会话 B 中切换到“全部笔记”后仍可查看；切换“当前会话”后正确过滤。

### AC-005 工作区筛选

当前工作区筛选展示该工作区不同会话产生的全部匹配笔记，不改变笔记本身的可见性。

### AC-006 标签管理

标签重命名后所有关联笔记同步更新；合并标签不会产生重复关联；删除标签不会删除笔记。

### AC-007 Markdown 导出

用户可以在列表中勾选任意多条笔记并导出为一个 UTF-8 `.md` 文件。文件保留所选笔记的 Markdown 正文、原文引用、标签、时间和来源信息，可直接在 Obsidian、Typora、VS Code 或其他标准 Markdown 工具中打开。

### AC-008 来源回链

从历史笔记打开来源，至少进入原会话；消息和锚点可用时滚动并突出精确引用。

### AC-009 归档会话

来源会话归档后笔记仍可查看；点击来源时可在归档中打开，或经用户确认后恢复并打开。

### AC-010 删除会话后的笔记

来源会话被删除后，笔记、标签和引用快照仍完整可读，并显示“来源不可用”。

### AC-011 数据可靠性

模拟无效数据或存储读取失败时，插件不得将已有数据覆盖为空集合。

### AC-012 多页面并发

两个 DSH 页面修改不同笔记或标签时，不发生静默覆盖；冲突时提示刷新或重试。

### AC-013 性能

遵循 NFR-001，在 Web/Desktop 的已记录 Phase 0 目标环境分别测试：当前会话 100 条高亮、全局 2,000 条笔记，以含多行 Markdown 的代表性固定样本执行 30 次常规搜索，输入到结果更新的 p95 小于 150ms（不含未触发查询的主动防抖等待，另记录防抖时长）；滚动/编辑过程中插件引起的持续主线程卡顿不得出现。导出 5,000 条笔记时可以继续滚动、输入和取消操作，记录耗时、最大主线程长任务与内存。测试报告列明设备、DSH/插件版本、数据体积及冷/热状态，不用“感觉不卡”代替指标。

### AC-014 卸载安全

卸载插件不自动删除用户数据；再次安装后须能重新加载保留的主存储。另在受控测试环境以本插件 JSON 备份执行 FR-104A：校验和预览、二次确认、保护当前介质、整库恢复；成功后笔记（含回收站）、标签、设置、来源及锚点完整一致。取消/无效备份/提交失败均不改旧库。此恢复通道属于 MVP，不以 P1 通用导入代替。

### AC-015 原文改写笔记

用户选择“基于原文改写”后，编辑器以原文副本作为初稿。修改后保存为 `manual`：正文是用户修改后的内容，原始引用保持不变，来源和标签保留。导出文件可同时展示“我的改写”和“原文引用”。从笔记面板空白创建的 `manual` 不要求原文引用。

### AC-016 快速 TODO 标签划线

用户选中原文，展开“划线”的二级菜单并选择 TODO，无需打开正文编辑器即可创建带 TODO 标签的 `highlight`。该笔记可通过 TODO 标签筛选，刷新后标签仍在；不创建任务状态、完成时间或截止日期。

### AC-017 快速创建普通标签

用户从划线二级菜单进入“选择/新建标签”，可输入新标签并保存到所选原文。新标签进入全局标签字典，后续可用于其他笔记；重复点击保存不得重复创建相同笔记或标签。

### AC-018 宿主存储与内容保真

创建含加粗、列表、链接、多行代码的笔记和改写内容，保存后刷新页面并重启 DSH，正文字符串、原始引用、来源、锚点及标签关联保持一致。修改改写正文不改变原始引用。持久化失败时不提示保存成功，旧数据保留且编辑内容可重试。

### AC-019 存储与导出独立

插件运行不需要安装独立 SQLite 驱动，不自动生成每条笔记的 Markdown 文件。勾选笔记导出后，外部修改导出的文件不改变笔记库。标签合并中模拟提交失败，笔记与标签保持操作前的完整关联，不出现半完成状态。

---

### AC-020 Web 与桌面双端支持

分别在 DSH Web 与 DSH 桌面版完成安装加载、普通划线、TODO 快捷标签、加入笔记、原文改写、手工新建、搜索筛选、标签管理、来源回链、单条/批量删除二次确认、Markdown 导出、JSON 备份和 FR-104A 受控恢复。两端重启后保存的内容仍可读取，导出文件均为可阅读的 UTF-8 Markdown。

来源打开应留在当前客户端；未支持的宿主能力需明确说明并提供等效体验。测试记录需注明 DSH 版本和平台，两端都通过才满足 MVP 发布要求。连接不同存储实例时不要求自动共享笔记，但必须明确展示数据隔离边界。

### AC-021 保存边界与标签规范化

选区少于 2 个非空白 Unicode 码点不触发快捷保存；8,000 码点上限内可创建，8,001 码点或最终 Markdown 引用超限时明确提示并阻止保存，选区保留且不截断。空正文 note 不落库，highlight 转 note 取消/校验失败/写入失败均保持原 highlight。TODO/todo、Ａ/A 创建不得产生重复名称键；重命名冲突不得自动合并。

### AC-022 受控恢复安全

分别验证取消、无效 Schema、更高未知版本、超出文件上限、保护旧库副本失败、提交失败、预览后另页修改和旧客户端提交：均不得覆盖有效旧库或静默清空损坏原件。合法恢复后业务字段完整一致，回收站与设置恢复；恢复前的旧写 token 被拒绝。无有效备份时只读提示，不提供自动清空修复。

### AC-023 输入框草稿

有当前会话时，复制 Markdown 或确认追加到最新输入框草稿可用；选择替换前明确确认，取消不改变草稿。不自动发送、不唤醒 Agent；无会话/能力不可用时说明原因并提供复制替代。在 Web/Desktop 分别验证。

## 15. 成功指标

首个可用版本重点观察：

1. 每周创建划线和笔记数量；
2. 划线转为带正文笔记的比例；
3. 标签使用率与平均每条笔记标签数；
4. 搜索与来源筛选使用次数；
5. Markdown 导出次数；
6. 来源回链成功率；
7. 归档会话回链成功率；
8. 原始 Markdown 保存成功率与纯文本降级率；
9. 高亮恢复成功率；
10. 数据写入、迁移和标签合并错误数；
11. 插件导致 DSH UI 卡顿或崩溃的次数。

这些指标是试用观察目标，不构成隐含的 MVP 诊断页或埋点开发需求。MVP 使用受控验收记录与用户主动反馈观察，不收集远程遥测。专用本地统计页及统计导出属于后续增强，需另行定义 FR 和隐私范围。

## 16. 风险与待验证问题

### 16.1 原始 Markdown 获取能力

这是 Phase 0 的最高优先级风险。浏览器 Selection 只天然提供渲染后的文本，不保证能够反推出原始 Markdown。需要确认 DSH 是否暴露消息源 Markdown和 source position。

### 16.2 Markdown 局部映射

即使能取得整条消息 Markdown，将 DOM Range 映射到源文偏移仍可能因以下结构变复杂：

- 链接文本与 URL；
- Markdown 标记符号不显示；
- 代码围栏；
- 表格；
- HTML；
- 同文本重复出现；
- Markdown 渲染器自动变换空白。

必须允许 `plain_text` 降级。

### 16.3 消息标识稳定性

需要确认 Client 是否稳定提供 messageId。若不能，需要通过会话数据服务或 Host 会话日志建立映射。

### 16.4 Web 与桌面双端加载

需要分别确认 Web 与桌面的安装入口、Profile、Host 运行环境和客户端插件贡献加载。尤其要验证桌面是否可复用 `platform: web` 的 Client Bundle、对应 UI Slot 是否可用、文件保存与来源打开的行为是否不同。

桌面插件加载不能以浏览器端加载成功代替验证。若两端的 Host 存储命名空间不同，应明确告知数据隔离边界，不承诺自动同步。

### 16.5 长会话虚拟化

未挂载消息无法立即恢复 Range。需要在消息出现后协调，不能将未挂载误判为来源失效。

### 16.6 相同文本重复出现

仅以选中文字匹配会定位错误。必须组合 messageId、exact、prefix、suffix、offset 和 occurrence。

### 16.7 归档会话 API

需要验证 DSH 是否支持：

- 查询时包含归档会话；
- 通过 sessionId 打开归档会话；
- 恢复归档会话；
- 获取会话归档状态。

若缺少 API，至少保证笔记可读和来源状态明确。

### 16.8 DSH Slot 变更

社区插件依赖的 Slot 可能随 DSH 版本变化。需要封装 DSH Adapter，并维护兼容性矩阵。

### 16.9 Storage Domain 能力

存储方向已确定为 DSH 自带存储服务，尚未确定其具体 API 和持久化能力。需验证命名空间隔离、容量限制、写入确认、版本控制、原子更新、备份和跨进程并发行为。

不要求宿主必须提供多表事务：若单条更新可靠且原子，可采用笔记与标签的整体逻辑快照。若只能局部写入，不能假设插件层串行队列即可保证掉电或跨进程一致性。能力不足时应明确阻断条件并另行评估方案，不自动退回裸文件覆盖或引入独立数据库。

## 17. 已确定决策、技术验证与后续事项

### 17.1 已确定 MVP 产品决策

确认依据：2026-10-02 用户同意按评审解释中的收敛建议修改文档。本表替代旧版 14 项开放清单；它确认产品行为，不代表宿主 API 或插件已验证。

| 决策 | 确定结论 | 对应规则 |
|---|---|---|
| 名称 | 包/仓库 `dsh-session-notebook`，界面“AI 笔记” | §1、§18；npm 名称可用性发布前核对 |
| 编辑器 | Markdown 文本编辑 + 预览切换；无所见即所得/强制分屏 | FR-030、§8.4 |
| 默认快捷标签 | TODO、重要、待验证，普通 Tag ID，可调整/隐藏/删除 | FR-003、FR-041 |
| note 空正文 | 仅允许空编辑草稿；保存须有引用及非空正文，转换成功才改变类型 | §5.2、FR-030/034、§9.1 |
| 超长引用 | 默认 8,000 Unicode 码点，超限提示并阻止保存，不截断 | FR-001 |
| Markdown 降级 | 无法精确映射保存选中纯文本并标 plain_text，不替换整条消息 | FR-011 |
| 标签名称 | trim 显示名；NFKC + trim + locale-independent lowercase 名称键去重 | FR-040 |
| 回收站 | 普通删除必入回收站，无自动过期，永久删除另确认 | FR-035 |
| 导出 | 默认沿当前列表顺序，不新增默认会话分组模板 | FR-083/084、FR-056 |
| 输入框写入 | MVP，仅经用户确认追加/替换草稿，不自动发送 | FR-055 |
| 数据恢复 | 本插件完整 JSON 的受控整库恢复纳入 MVP；增量合并为 P1 | FR-104A/B |
| 非范围 | 整条消息收藏、Tool 消息摘录、通用导入不进入 MVP | §12.2、§17.3 |

### 17.2 发布前技术验证项

这些事项不再作为产品边界待议，但验证失败可能阻断相应实现或发布，详见 §16 与开发指南：

1. Phase 0 记录 Web/Desktop 的实际 DSH 版本、Host/Profile/存储边界，发布前形成支持版本矩阵。
2. Storage Domain 原子提交、耐久、失败回滚、损坏副本与恢复点、多 Host 安全边界。
3. 正式 Host/Client 通信、原生 Tab/等效抽屉、消息身份、原始 Markdown 与局部映射能力。
4. 归档查询/打开/确认恢复、长会话消息定位、输入框草稿及双端导出/复制行为。
5. MVP 不依赖 DSH Deep Link：仅在协议已验证且稳定时增加可点击链接，否则导出来源文本；不能为了 Deep Link 延迟核心导出。
6. npm 包名是否可用；如必须改为 scoped package，发布前同步 manifest、factory id、patch 与安装资料，不改变产品行为。

### 17.3 后续版本事项（不阻塞 MVP）

- P1：FR-005 整条消息收藏；Tool 消息摘录需另定义角色/内容边界后评估。
- P1：FR-104B 增量导入与合并；旧 `dsh-plugin-session-notes` 数据兼容需独立预览、校验与保真限制说明，不自动读写旧介质。
- 后续评估：Codex/MCP 稳定共享协议、Agent Tools、结构化 TODO、跨设备同步；MVP 不实现或自动注入历史笔记。

Phase 0 可以开展技术验证；后续开发按已确定产品规则及验证结论推进，不再将上表决策重复标记“待产品确认”。

## 18. 命名结论

已确定名称（2026-10-02）：

```text
产品中文名：DSH AI 会话笔记本
产品英文名：DSH Session Notebook
npm/仓库名：dsh-session-notebook
界面短名称：AI 笔记
```

不推荐将产品命名为：

- Conversation Notes & Actions：过度强调行动项；
- Task Notes：容易被理解为任务管理器；
- Sticky Notes：无法表达标签、搜索、来源和导出；
- Dialogue Notes：与 DSH 的 Session 术语不一致。

`dsh-session-notebook` 清楚表达：这是围绕 DSH Session 建立的长期笔记本，而不是会话工作流工具。

## 19. 总结

产品核心闭环：

```text
看到重要内容
→ 划线或写笔记
→ 保留 Markdown 和来源
→ 使用标签组织
→ 按会话、工作区和关键词检索
→ 回到原会话继续阅读
→ 导出 Markdown 长期保存
```

产品差异化在于：

1. 笔记与 AI 会话原文强关联；
2. 尽可能保留原始 Markdown，而不是只有纯文本截图式引用；
3. 所有笔记形成全局笔记库，当前会话和工作区只是筛选维度；
4. 标签具有独立字典，可重命名、合并和管理；
5. 会话归档或删除后，笔记和引用快照仍然存在；
6. Markdown 导出让数据能够脱离插件长期保存；
7. 产品专注笔记，不扩张为会话工作流或重型 TODO 系统。
